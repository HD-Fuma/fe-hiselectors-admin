# 관리자 작업 탭 정돈 디자인

## 목표

현재의 회색 받침과 위로 솟은 둥근 탭 형태를 없애고, 관리자 화면의 짙은 사이드바와 고밀도 본문 사이를 조용하게 연결하는 플랫 작업 탭 바로 바꾼다. 화면 이동, 열린 탭 유지, 활성 탭 전환, 닫기 동작은 그대로 유지한다.

## 선택한 방향

`흰색 플랫 레일 + 얇은 청록 활성 기준선`을 사용한다.

- 탭 레일은 흰색 배경과 아래쪽 1px 구분선만 가진다.
- 각 탭은 돌출 테두리와 상단 둥근 모서리를 제거한다.
- 활성 탭은 진한 글자, 매우 옅은 청록 배경, 아래쪽 2px 청록선으로 구분한다.
- 비활성 탭은 차분한 회색 글자를 사용하고 hover 시에만 옅은 청록 배경을 보인다.
- 닫기 버튼은 활성 탭에서는 보이고, 비활성 탭에서는 hover 또는 키보드 focus 때만 나타난다. 비활성 버튼은 레이아웃과 탭 순서에 그대로 둔 채 `opacity`로만 숨기고, 마우스 오작동을 막기 위해 숨은 동안만 pointer event를 받지 않는다.
- 여러 탭이 가로폭을 넘으면 레일 안에서 한 줄 가로 스크롤한다. 고정 높이 안에서 운영체제별 스크롤바가 탭을 자르지 않도록 네이티브 스크롤바만 숨기되, 키보드 탭 이동과 활성 탭 자동 노출로 탐색은 유지한다. 활성 탭이 바뀔 때 문서가 아닌 레일의 `scrollLeft`만 필요한 만큼 조정해 항상 가시 영역에 두며, 탭 때문에 문서 전체 폭이 늘어나지 않는다.

이 디자인의 시그니처는 활성 화면과 본문을 하나로 이어 보이게 하는 얇은 청록 기준선이다. 기존 브랜드 색을 그대로 사용하며 새로운 장식이나 아이콘은 추가하지 않는다.

## 접근성과 반응형

- 현재 `aria-current="page"`, 작업 탭 내비게이션 이름, 닫기 버튼 접근성 이름을 유지한다.
- 링크와 닫기 버튼의 `:focus-visible` 윤곽을 유지한다.
- 숨겨진 비활성 닫기 버튼도 키보드 탭 순서에 남고, focus를 받는 순간 표시된다.
- hover를 사용할 수 없는 입력 환경에서는 모든 닫기 버튼을 표시한다.
- 탭은 줄바꿈하지 않으며 좁은 작업 영역에서는 레일 내부만 스크롤한다.

## 검증

- 두 화면을 방문해 활성·비활성 탭이 함께 있는 상태를 만든다.
- 레일이 흰색이고 활성 탭 아래에 2px 청록선이 있는지 브라우저 계산 스타일로 검증한다.
- 비활성 닫기 버튼이 기본 상태에서는 숨고 hover 및 키보드 focus 시 나타나며 포커스 윤곽을 유지하는지 검증한다.
- touch context에서 모든 닫기 버튼이 보이는지 검증한다.
- 많은 화면을 연 뒤 탭이 한 줄로 내부 스크롤되고, 마지막 활성 탭이 가시 영역에 있으며, 문서 전체 폭은 변하지 않는지 검증한다.
- 긴 문서에서 화면을 아래로 스크롤한 뒤 탭이 바뀌어도 문서의 세로 위치가 움직이지 않는지 검증한다.
- 접근성 이름과 활성 링크의 `aria-current="page"`를 다시 확인한다.
- 기존 탭 열기·닫기 단위 테스트와 관리자 셸 기하 테스트를 유지한다.
- 전체 테스트, lint, build와 실제 브라우저 스크린샷을 확인한다.
