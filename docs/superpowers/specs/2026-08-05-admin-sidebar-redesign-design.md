# FUMA 관리자 단일 사이드바 개편 디자인 명세

- 작성일: 2026-08-05
- 대상: FUMA 셀렉터스 관리자 업무 셸
- 상태: 사용자 승인
- 범위: 관리자 사이드바, 상단 유틸리티 바, 관련 디자인 토큰과 테스트

## 1. 배경

현재 관리자 셸은 `40px 아이콘 레일 + 205px 마이메뉴 + 전체메뉴 오버레이`의 세 가지 탐색 수단을 함께 사용한다. 현재 업무군의 메뉴만 마이메뉴에 보이기 때문에 다른 업무군으로 이동하려면 전체메뉴를 별도로 열어야 한다. 즐겨찾기와 메뉴 편집 버튼도 노출되지만 실제 기능은 없다.

이번 개편은 탐색 구조를 하나로 줄이고 모든 관리자 메뉴를 한 화면에서 확인할 수 있게 하는 것이 목적이다. 기능 화면, 로그인, 데이터 fixture와 업무 동작은 변경하지 않는다.

## 2. 결정 사항

### 2.1 선택한 방향

`248px 짙은 차콜 고정형 단일 사이드바`를 사용한다.

- 사이드바는 항상 펼쳐진 상태로 유지하며 축소 기능을 제공하지 않는다.
- 8개 업무군과 중복 제거된 14개 메뉴 링크를 모두 표시한다.
- 업무군은 섹션 제목으로 구분하고 모든 섹션을 기본적으로 펼친다.
- 메뉴가 뷰포트 높이를 넘으면 내비게이션 영역만 세로 스크롤한다.
- 브랜드는 기존 전역 상단 바에서 사이드바 상단으로 이동한다.
- 우측 상단 바는 화면 맥락과 관리자 유틸리티 정보만 담는다.

### 2.2 검토 후 제외한 방향

1. 밝은 흰색 사이드바: 본문과의 경계가 약하고 기존 현대 계열 관리자 시스템의 시각 정체성이 줄어 제외한다.
2. 아코디언 메뉴: 공간은 절약되지만 모든 메뉴를 즉시 확인하려는 요구와 맞지 않아 제외한다.
3. 축소 가능한 아이콘 사이드바: 이중 탐색 구조를 다시 만들고 상태 관리가 추가되므로 제외한다.

## 3. 정보 구조

사이드바 메뉴는 `NAV_GROUPS`와 `getGroupMenuItems()`를 단일 출처로 사용한다. 상세·수정·등록 라우트는 중복 링크를 만들지 않고 상위 메뉴를 활성화한다.

| 업무군 | 메뉴 |
| --- | --- |
| 크리에이터 | 크리에이터 목록, 제안 이력 |
| 셀렉터스 | 기수 관리, 셀렉터스 현황, 자격 관리 |
| 지원자 | 지원자 목록 |
| 캠페인 | 캠페인 관리 |
| 콘텐츠 | 콘텐츠 검수, 위반 관리 |
| 성과 | 성과 대시보드, 크리에이터 분석, 콘텐츠 분석 |
| 정산 | 정산 관리 |
| 시스템 | 공지사항 |

사이드바의 세로 구조는 다음 순서를 따른다.

1. 브랜드 영역
2. 전체 메뉴 내비게이션
사이드바에는 별도의 하단 유틸리티를 두지 않는다. 관리자 정보, 설정, 로그아웃은 상단 유틸리티 바에만 표시한다.

## 4. 관리자 셸 레이아웃

### 4.1 기본 구조

- 전체 셸은 `사이드바 + 워크스페이스`의 2열 구조다.
- 사이드바 너비는 `248px`이며 `position: sticky`, `top: 0`, `height: 100dvh`로 뷰포트에 고정한다.
- 사이드바 내부는 `68px minmax(0, 1fr)`의 2행 grid로 구성하고 가운데 내비게이션에만 `overflow-y: auto`를 적용한다.
- 워크스페이스는 `상단 유틸리티 바 + 작업 탭 + 본문` 순서다.
- 상단 유틸리티 바 높이는 `44px`로 한다. 사용자 정보와 유틸리티를 수용하되 고밀도 화면의 수직 공간을 과도하게 차지하지 않는 값이다.
- 기존 최소 화면 너비 `1280px` 정책과 고밀도 업무 화면의 가로 스크롤 정책은 유지한다.
- 공통 모달은 단일 사이드바 너비를 기준으로 화면 중심을 계산한다.

### 4.2 브랜드 영역

- 높이: `68px`
- 기본 표기: `FUMA`
- 보조 표기: `ADMIN CONSOLE`
- 왼쪽 정렬하며 청록색 사각 심볼과 흰색 브랜드명을 조합한다.
- 클릭 기능은 추가하지 않는다.

### 4.3 상단 유틸리티 바

- 기존의 단독 `FUMA 관리자 시스템` 텍스트는 제거한다.
- 왼쪽에는 현재 업무군과 화면명을 `업무군 / 화면명` 형식으로 표시한다.
- 오른쪽에는 정적 사용자 이름 `관리자`, 역할 `FUMA 운영자`, 설정, 로그아웃을 간결하게 배치한다.
- 사용자 메뉴 드롭다운 같은 새로운 기능은 만들지 않는다.
- 설정과 로그아웃은 정적 버튼이며 기존 프로토타입의 기능 범위를 유지한다.

## 5. 사이드바 시각 시스템

### 5.1 색상

기존 브랜드 청록색은 유지하고 사이드바 전용 중립색을 토큰으로 추가한다.

| 역할 | 값 |
| --- | --- |
| 사이드바 배경 | `#202826` |
| 사이드바 보조 배경 | `#27312F` |
| 기본 메뉴 텍스트 | `#C9D2CF` |
| 그룹 제목 | `#82918D` |
| 활성 메뉴 배경 | `#116F60` |
| 활성 메뉴 텍스트 | `#FFFFFF` |
| hover 배경 | `#2C3835` |
| 구분선 | `rgba(255, 255, 255, 0.08)` |
| 브랜드·포커스 강조 | 기존 `--hsas-teal-accent` |

### 5.2 크기와 간격

- 사이드바 좌우 여백: `12px`
- 그룹 간격: `14px`
- 그룹 제목 높이: `22px`
- 메뉴 행 높이: `34px`
- 메뉴 행 모서리: `6px`
- 아이콘: `16px`
- 그룹 제목: `11px`, 700, 약한 자간
- 메뉴: `12px`, 500
- 활성 메뉴: `12px`, 700

### 5.3 메뉴 표현

- 각 업무군 제목 옆에는 `lucide-react` 선형 아이콘을 하나씩 배치하고 장식 아이콘은 `aria-hidden="true"`로 숨긴다.
- 아이콘은 `크리에이터=UsersRound`, `셀렉터스=BadgeCheck`, `지원자=ClipboardList`, `캠페인=Megaphone`, `콘텐츠=FileSearch`, `성과=BarChart3`, `정산=WalletCards`, `시스템=Settings2`로 고정한다.
- 그룹 제목은 메뉴 링크보다 작고 흐리게 표시해 계층을 만든다.
- 활성 링크는 청록색 채움, 흰색 텍스트, 좌측 `3px` 강조선으로 표시한다.
- hover는 한 단계 밝은 차콜 배경을 사용한다.
- 현재 업무군만 별도 카드로 감싸지 않는다. 전체 메뉴의 밀도와 정렬을 일정하게 유지한다.
- 메뉴마다 별 아이콘, 핀, 편집 핸들을 제공하지 않는다.

## 6. 제거 범위

다음 UI와 상태를 완전히 제거한다.

- `IconRail`
- `MyMenu`
- `MegaMenu`와 전체메뉴 오버레이
- `?fixture=mega-menu` 시각 fixture
- 아이콘 레일의 즐겨찾기, 전체메뉴, 메뉴 편집 버튼
- 화면 제목의 `현재 화면 즐겨찾기` 버튼
- 메가메뉴 열림 상태, 포커스 트랩, 닫기 처리
- `--hsas-rail-width`와 기존 `--hsas-menu-width`에 의존하는 2중 레이아웃 계산

설정과 로그아웃은 제거하지 않고 상단 유틸리티 바에만 한 번 표시한다.

## 7. 컴포넌트 구조

### 7.1 신규 컴포넌트

`AdminSidebar`

- `activeRoute`와 `currentPath`를 입력받는다.
- `NAV_GROUPS`를 순회하며 모든 그룹을 렌더한다.
- 각 그룹의 링크는 `getGroupMenuItems()`로 만든다.
- `menuLabel === activeRoute.menuLabel`이면 섹션 선택 상태를 적용한다.
- 활성 상태는 미래의 중복 라벨에 대비해 `group + menuLabel`을 함께 비교한다.
- 상세·수정·등록 라우트를 포함해 현재 섹션을 대표하는 활성 링크에 `aria-current="page"`를 적용한다.

`AdminTopbar`

- 활성 업무군과 화면명을 표시한다.
- 정적 사용자 이름 `관리자`, 역할 `FUMA 운영자`와 설정·로그아웃 유틸리티를 표시한다.
- 드롭다운이나 인증 동작을 추가하지 않는다.

### 7.2 변경 컴포넌트

`AppShell`

- 메가메뉴 관련 상태와 query 처리 코드를 제거한다.
- `AdminSidebar + workspace` 구조로 단순화한다.
- `WorkTabs`와 `Outlet`은 유지한다.

`PageHeader`

- 즐겨찾기 버튼을 제거한다.
- 제목, 화면 코드, 새로고침은 유지한다.

### 7.3 제거 후보 컴포넌트

- `IconRail.tsx`
- `MyMenu.tsx`
- `MegaMenu.tsx`

참조가 완전히 사라지고 테스트가 통과하면 파일도 삭제한다.

## 8. 동작과 상태

- 사이드바 링크의 기존 React Router 이동만 유지한다.
- 메뉴 그룹은 접히지 않으며 별도 상태를 갖지 않는다.
- 즐겨찾기, 메뉴 편집, 전체메뉴 열기 동작은 존재하지 않는다.
- 세로 스크롤 위치 저장 기능은 추가하지 않는다.
- 상세·수정·등록 화면에서는 상위 메뉴가 시각적 선택 상태와 `aria-current="page"`를 함께 유지한다.
- 로그인 라우트에는 관리자 셸과 사이드바가 렌더되지 않는다.

## 9. 접근성

- 전체 메뉴는 하나의 `nav`와 명확한 `aria-label="관리자 메뉴"`를 사용한다.
- 업무군 제목은 시각·문서 구조상 각 링크 묶음의 제목이 되도록 연결한다.
- 링크는 키보드로 순서대로 접근 가능해야 한다.
- 활성 링크의 색상 대비는 WCAG AA를 충족해야 하며 색상 외에 강조선과 굵기로도 상태를 구분한다.
- focus-visible은 기존 전역 청록색 포커스 링을 유지하되 어두운 배경에서 잘리거나 묻히지 않게 한다.
- 사이드바 스크롤 영역은 휠, 트랙패드, 키보드 탐색을 방해하지 않는다.
- 모션은 사용하지 않으며 reduced-motion 정책을 그대로 유지한다.

## 10. 반응형과 오버플로

- 데스크톱 관리자 화면을 우선하며 사이드바는 모든 지원 너비에서 `248px`로 고정한다.
- 최소 셸 너비 `1280px` 아래에서는 기존 정책대로 문서 가로 스크롤을 허용한다.
- 높이가 낮을 때 브랜드는 고정하고 중앙 메뉴 영역만 스크롤한다.
- 1310×741과 1440×900에서 브랜드, 스크롤 메뉴, 상단 유틸리티 바와 본문이 겹치지 않아야 한다.

## 11. 디자인 토큰 정리

이번 변경에서 사이드바에 필요한 토큰을 `tokens.css`에 추가한다.

- 너비와 상단 바 높이
- 사이드바 배경·보조 배경·텍스트·hover·active·border
- 메뉴 행 높이와 모서리
- 필요 시 그림자와 z-index

기존 짧은 별칭 토큰(`--rail-width`, `--menu-width`, `--topbar-height`)은 실제 사용처를 확인한 뒤 중복을 제거한다. 기능 화면 전체의 하드코딩된 색상 정리는 이번 범위에 포함하지 않는다.

## 12. 검증 기준

### 12.1 컴포넌트 테스트

- 관리자 셸에 단일 사이드바, 상단 바, 작업 탭, 본문이 존재한다.
- 아이콘 레일, 마이메뉴, 전체메뉴 대화상자가 존재하지 않는다.
- 즐겨찾기와 메뉴 편집 버튼이 어느 관리자 화면에도 존재하지 않는다.
- `관리자 메뉴` nav 내부에 8개 업무군과 정확히 14개 메뉴 링크가 모두 렌더된다.
- 각 대표 라우트에서 올바른 메뉴가 선택된다.
- 상세·수정·등록 라우트에서 상위 메뉴가 선택된다.
- 로그인은 관리자 셸 밖에 유지된다.

### 12.2 시각 테스트

- 사이드바 너비는 `248px ± 3px`다.
- 상단 유틸리티 바 높이는 `44px ± 2px`다.
- 워크스페이스 너비는 셸 너비에서 사이드바 너비를 뺀 값과 일치한다.
- 1310×741에서 브랜드가 고정된 채 메뉴 영역만 스크롤 가능하고 마지막 메뉴까지 접근할 수 있다.
- 1440×900에서 활성 메뉴, hover/focus 상태와 텍스트 잘림을 확인한다.
- 공통 모달 backdrop은 사이드바까지 포함해 전체 뷰포트를 덮고 사이드바·상단바보다 높은 z-index를 사용한다.
- 모달 패널은 backdrop에 `padding-left: calc(var(--hsas-sidebar-width) + 16px)`를 적용해 워크스페이스를 기준으로 시각적 중앙에 위치한다.

### 12.3 회귀 검증

- TypeScript 컴파일, 단위 테스트, 프로덕션 빌드가 성공한다.
- 기존 모든 관리자 라우트와 업무 화면이 렌더된다.
- 로그인 화면의 구조와 시각 계약은 변경되지 않는다.
- 브라우저 콘솔 오류가 없다.
- `AppShell.test.tsx`와 `routeCoverage.test.tsx`의 메가메뉴 fixture·포커스 트랩 계약은 단일 사이드바 메뉴 노출 계약으로 교체한다.
- `admin.spec.ts`의 메가메뉴 시각 checkpoint와 `login-shell.spec.ts`의 40px 레일·205px 메뉴 고정 계약은 248px 단일 사이드바 계약으로 교체한다.

## 13. 완료 조건

- 관리자 탐색 구조가 하나의 고정형 사이드바로 통합된다.
