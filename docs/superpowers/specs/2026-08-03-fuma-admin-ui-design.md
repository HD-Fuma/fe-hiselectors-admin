# FUMA 관리자 UI 디자인 명세

- 작성일: 2026-08-03
- 대상: FUMA 셀렉터스 관리자 정적 UI 프로토타입
- 기술 스택: React, TypeScript, Vite
- 근거 자료: `FUMA_기능명세서 (4).xlsx`의 `관리자` 시트와 사용자 제공 현대홈쇼핑 관리자 참고 이미지 9개

> **현재 관리자 셸 계약:** 2026-08-05에 승인된 [FUMA 관리자 단일 사이드바 개편 디자인 명세](./2026-08-05-admin-sidebar-redesign-design.md)가 관리자 셸, 내비게이션, 관련 디자인 토큰과 테스트의 권위 있는 기준이다. 이 문서는 그 외 화면·데이터 요구사항의 원본 명세로 유지하며, 두 문서가 충돌하면 2026-08-05 명세를 따른다.

## 1. 목표와 범위

현대홈쇼핑 협력사 시스템의 시각 언어를 그대로 재현한 FUMA 관리자 화면을 만든다. 결과물은 기능 개발 이전의 UI 검토용 정적 프로토타입이다.

- P0/P1 관리자 기능은 실제 화면처럼 완성된 목록, 상세, 폼 UI로 제공한다.
- P2/P3 기능은 동일한 디자인 시스템을 사용하는 대표 목록 또는 폼 UI로 포함한다.
- 메뉴 및 화면 이동은 결과물을 확인하기 위한 최소한의 라우팅만 제공한다.
- 검색, 승인, 반려, 삭제, 발송, 업로드, 저장은 실제 업무 처리를 하지 않는다.
- API, 백엔드, 인증, 서버 상태, 전역 상태 관리, 실제 파일 처리는 범위에서 제외한다.

## 2. 결정한 접근법

선택한 접근법은 "단일 사이드바 전체 탐색 + 핵심 화면 상세 구현"이다.

- 모든 관리자 업무군을 고정형 단일 사이드바에서 확인할 수 있다.
- 반복되는 35개 완성 기능을 기능별로 모두 분리하지 않고 업무 맥락이 같은 기능은 하나의 화면에 통합한다.
- P0/P1 기능은 실제 운영 화면처럼 검색 조건, 표, 상세 정보, AI 리포트, 상태 및 액션 영역까지 표현한다.
- P2/P3 기능은 정보 구조를 검토할 수 있는 수준의 대표 UI를 제공한다.

검토 후 제외한 접근법:

1. P0 기능만 제작: 전체 관리자 정보 구조를 검토할 수 없어 제외한다.
2. 35개 완성 기능을 모두 별도 화면으로 제작: 중복 화면이 많고 정적 UI 검토 목적에 비해 과도해 제외한다.

## 3. 화면 정보 구조

### 3.1 인증

- `/login`: 관리자 로그인

### 3.2 크리에이터 풀

- `/creators`: 크리에이터 목록, 다중 조건 검색
- `/creators/:creatorId`: 기본 정보, 활동 지표, AI 요약 리포트, 영입 제안 UI
- `/proposals`: 제안 대상, 채널, 발송 시각, 상태를 보여주는 제안 이력

### 3.3 셀렉터스 관리

- `/cohorts`: 기수 생성 및 활동·모집 기간 관리
- `/selectors`: 기수별 셀렉터스 목록과 활동 현황
- `/selectors/qualifications`: 경고, 박탈, 수료, 블랙리스트 및 수동 자격 관리

### 3.4 지원자 심사

- `/applicants`: 지원자 목록, 상태 및 정량 지표
- `/applicants/:applicantId`: 지원자 기본 정보, SNS 지표, AI 요약 리포트, 승인·반려 UI

### 3.5 캠페인

- `/campaigns`: 캠페인 목록, 기간 및 상태
- `/campaigns/new`: 캠페인 등록 폼
- `/campaigns/:campaignId/edit`: 캠페인 수정 폼

### 3.6 콘텐츠 검수 및 위반 관리

- `/content/reviews`: 신규, 위반 후 수정, 일반 수정 콘텐츠 검수 대기열
- `/content/reviews/:contentId`: 원본 콘텐츠, AI 요약, 변경 사항 대조, 검수 액션
- `/content/violations`: 위반 유형, 처리 상태, 패널티 횟수 및 안내 발송 UI

### 3.7 성과

- `/performance`: 캠페인·셀렉터스별 클릭, 구매 전환, 전환율 요약 대시보드
- `/performance/creators`: 크리에이터 영향력 분석 표
- `/performance/contents`: 콘텐츠 영향력 분석 표

### 3.8 정산 및 시스템 관리

- `/settlements`: 월별 지급액 확인, 수정, 확정 상태 UI
- `/system/notices`: 공지사항 목록 및 작성·수정 폼

## 4. 전역 레이아웃

### 4.1 로그인

로그인은 가장 최근에 제공된 `스크린샷 2026-08-03 21.12.40.png`를 기준으로 한다. 이전의 사진 분할형 로그인은 사용하지 않는다.

- 전체 배경은 매우 밝은 회색이다.
- 화면 중앙에 약 460×570px의 흰색 로그인 카드가 위치한다.
- 카드는 1px 회색 테두리, 약 16px 모서리, 낮은 회색 그림자를 사용한다.
- 상단에는 `더현대Hi | Partners`와 `더현대Hi 협력사 업무지원시스템` 문구를 배치한다.
- 아이디와 비밀번호 입력은 아이콘이 있는 밑줄형 필드다.
- `아이디 저장` 체크박스 아래에 청록색 로그인 버튼과 짙은 회색 계정 지원 버튼을 배치한다.
- 카드 오른쪽에는 `신규입점문의`, `광고신청/안내`, QR, `파트너스 APP 다운로드`를 세로로 배치한다.

### 4.2 관리자 업무 셸

- 기준 화면 너비는 1440px이며 최소 너비는 1280px이다.
- 관리자 셸은 `248px` 고정형 단일 사이드바와 워크스페이스의 2열 구조다.
- 사이드바는 `100dvh` 높이로 고정하고 브랜드 영역 아래의 내비게이션만 세로 스크롤한다.
- 워크스페이스 상단 유틸리티 바 높이는 `44px`이며 현재 업무 맥락과 관리자 정보를 표시한다.
- 워크스페이스는 상단 유틸리티 바, 작업 탭, 화면 제목, 검색 영역, 탭 또는 단계 영역, 본문 순서로 쌓는다.
- 사이드바에는 8개 업무군과 중복 제거된 14개 메뉴 링크를 항상 펼쳐 표시한다.
- 좁은 화면에서 구조를 모바일형으로 바꾸지 않고 원본과 같이 가로 스크롤을 허용한다.

세부 치수, 메뉴 상태, 접근성 계약은 [2026-08-05 단일 사이드바 개편 명세](./2026-08-05-admin-sidebar-redesign-design.md)를 따른다.

## 6. 화면별 핵심 UI

### 6.1 목록 화면

목록 화면은 `제목 → 검색 패널 → 결과 건수/일괄 액션 → 고밀도 표 → 페이지네이션` 구조를 공유한다. 표의 주요 액션은 텍스트 버튼 또는 작은 테두리 버튼으로 표시한다.

### 6.2 상세 및 심사 화면

상단에는 대상의 기본 식별 정보와 상태를 표시한다. 중간에는 SNS 지표 및 AI 요약 리포트를 두고, 하단에는 검토 의견과 승인·반려 액션을 배치한다. 콘텐츠 검수 상세에서는 원문과 변경 내용을 나란히 비교한다.

### 6.3 등록 및 수정 화면

참고 이미지의 상품 등록 화면처럼 단계 또는 섹션 탭을 제공한다. 필드는 좌측 라벨과 우측 컨트롤로 구성된 고밀도 행이며, 긴 화면의 주요 액션은 우측 상단과 하단에 반복한다.

### 6.4 성과 화면

참고 관리자 시스템의 평평한 시각 언어를 유지한다. 과도한 카드형 대시보드는 사용하지 않고 얇은 경계선, 요약 수치 띠, 필터, 표 및 단순 차트 영역으로 구성한다.

## 7. 데이터와 동작 경계

- 모든 화면 데이터는 TypeScript fixture로 정의한다.
- route parameter의 ID는 일치하는 fixture 상세 항목을 선택한다. 일치하지 않는 ID는 `대상을 찾을 수 없습니다` 상태를 렌더한다.
- 메뉴와 작업 탭의 화면 이동만 동작한다.
- 버튼, 검색 필드, 셀렉트, 체크박스는 시각적 상태를 표현하지만 업무 데이터를 변경하지 않는다.
- 외부 네트워크 요청은 발생하지 않는다.
- fixture가 없는 상세 경로는 동일 레이아웃의 `대상을 찾을 수 없습니다` 정적 상태를 보여준다.

## 8. 오류·빈 상태

기능 동작은 없지만 디자인 검토를 위해 다음 상태를 컴포넌트 사례로 포함한다.

- 검색 결과 없음
- 등록된 제안 이력 없음
- AI 리포트 생성 전
- 선택된 행 없음
- 상세 대상을 찾을 수 없음

오류 문구는 원본 관리자 시스템과 같은 간결한 업무 문체를 사용한다.

## 9. 검증 기준

- TypeScript 컴파일과 프로덕션 빌드가 성공해야 한다.
- 공통 컴포넌트와 대표 라우트가 렌더되는지 자동 테스트한다.
- 모든 메뉴 목적지가 존재하는지 라우트 스모크 테스트를 수행한다.
- 로그인은 사용자 제공 이미지의 원본 비율에서, 관리자 화면은 1310×741 및 1440×900에서 스크린샷을 확인한다.
- 단일 사이드바 `248px`, 상단 유틸리티 바 `44px`, 워크스페이스 폭, 폼 밀도, 표 행 높이와 청록색 비율을 확인한다.
- 8개 업무군과 14개 링크가 하나의 `관리자 메뉴` 내비게이션에 렌더되고, 낮은 뷰포트에서 브랜드는 고정된 채 내비게이션만 스크롤되어 마지막 `공지사항` 링크까지 접근 가능한지 확인한다.
- 1440×900에서 활성·hover·focus-visible 상태와 텍스트 잘림 여부를 확인한다.
- 별도 전체 메뉴 오버레이, 화면 즐겨찾기, 메뉴 편집 UI가 존재하지 않아야 한다.
- 브라우저 콘솔 오류와 잘린 핵심 텍스트가 없어야 한다.

## 10. 완료 조건

- 명세의 모든 관리자 업무군이 메뉴에 노출된다.
- P0/P1 대표 화면에서 요구 기능을 식별할 수 있다.
- P2/P3 대표 화면이 동일한 디자인 시스템으로 제공된다.
- 로그인은 최신 참고 이미지와 일치하고, 업무 화면은 기존 HSAS의 고밀도 시각 언어를 유지하면서 2026-08-05 단일 사이드바 계약을 충족한다.
- 관리자 탐색은 별도 팝업이나 즐겨찾기·메뉴 편집 UI 없이 하나의 고정형 사이드바로 통합된다.
- 실제 기능이 없어도 이해관계자가 전체 관리자 UI 구조와 화면 밀도를 검토할 수 있다.

## 11. 관리자 요구사항 커버리지

## 12. 콘텐츠 검수 유형 정의

세 유형은 하나의 상세 컴포넌트를 재사용하되 데이터 출처와 비교 방식, 라벨, 액션을 구분한다. 아래 상태는 UI fixture를 위한 표시 규칙이며 최종 업무 정책을 확정하는 구현은 아니다.

| 검수 유형 | 화면 라벨 | 이전 스냅샷 | 현재 스냅샷 | 강조 정보 | 표시 액션 |

## 15. 결정적 정적 상태 경로

업무 동작 없이도 빈 상태와 오류 상태를 확인할 수 있도록 URL query fixture를 사용한다.

- `/creators?fixture=empty`: 검색 결과 없음
- `/proposals?fixture=empty`: 제안 이력 없음
- `/creators/cr-001?fixture=ai-pending`: AI 리포트 생성 전
- `/applicants/ap-003?fixture=auto-rejected`: 자동 반려 기준과 사유
- `/content/reviews?fixture=no-selection`: 선택된 행 없음
- `/content/reviews/ct-002?fixture=violation-correction`: 위반 수정본 비교
- `/content/reviews/ct-003?fixture=edited`: 일반 수정본 비교
- `/creators/missing`: 상세 대상을 찾을 수 없음
- `/campaigns/new?fixture=product-modal`: 상품 선택 모달이 열린 캠페인 등록 화면

관리자 셸 내비게이션은 항상 펼쳐진 단일 사이드바이므로 별도의 셸 열림 fixture를 사용하지 않는다. 2026-08-03 구현의 전체 메뉴 오버레이 fixture는 2026-08-05 개편에서 제거되었다.

검색 컨트롤을 조작해 이 상태로 전환하는 기능은 만들지 않는다. 각 URL이 해당 fixture를 결정적으로 선택한다.
